# README 模板

按项目实际情况删减，不要留空段落。没有的内容直接去掉，不写“敬请期待”。

```markdown
<p align="center"><a href="在线地址"><img src="docs/demo.gif" alt="演示内容的描述" width="1000"></a></p>

<h1 align="center">项目名</h1>

<p align="center">一句话说明用户能得到什么，不靠技术名词。</p>

<p align="center">
  <a href="在线地址"><strong>在线体验</strong></a> ·
  <a href="README.en.md">English</a>
</p>

## 这是什么

两三句话说明解决什么问题、和常见做法有什么不同。

- 用户能感知到的特点（只写实际做到的）
- 用户能感知到的特点

## 快速开始

能复制就跑的最短步骤，写清前置条件。

## 工作原理

一张简图或一小段话。别人想改代码时，先看这里。

## 项目结构

只列别人需要知道的目录。

## 参与贡献

一句话，链接到 CONTRIBUTING.md。

## 致谢

引用的作品、素材、灵感来源，附作者和链接。

## 授权

代码用什么协议。不在该协议范围内的内容单独列出来。
```

## 写完检查

- [ ] 不滚动就能看到演示、一句话价值和入口
- [ ] 所有命令在干净环境实际跑过
- [ ] 所有链接和图片都能打开，图片有 alt
- [ ] 没有没做到的功能、没测过的数字
- [ ] 没有私人信息
- [ ] 第三方内容都有署名，并单独说明授权
